# Windows 远程软件部署与自动自愈设计

**状态：** 已获需求确认，待实现前审阅

**日期：** 2026-09-10

## 1. 目标

为新育智慧校园远程协助 Windows 客户端增加受控的远程软件部署能力。授权的远程控制端可以下发 `szxinyu.com` 根域名或其子域名下的 HTTPS 安装包地址，被控端可以先下载、再按检测结果静默安装；安装完成后，Windows 服务持续检查已登记的软件，软件被删除或卸载时自动重新下载并恢复安装。

第一版只支持 Windows，不改变 Android、macOS、Linux 的行为。

## 2. 已确认的范围与非目标

### 范围

- 仅处理 `.msi` 和 `.exe` 安装包。
- 支持“仅下载”和“下载并安装”两种远程操作。
- 安装包地址由已授权的远程端下发。
- 允许的 URL 必须使用 HTTPS，主机名必须是 `szxinyu.com` 或以 `.szxinyu.com` 结尾的子域名，例如 `update.szxinyu.com`。
- 安装前支持三种固定检测方式：MSI ProductCode、Windows 卸载注册表中的显示名称、指定的本地 EXE 路径。
- 自愈检查由已安装的 RustDesk Windows 服务执行，避免依赖登录用户或前台窗口。

### 非目标

- 不支持 Android 静默安装 APK。
- 不支持卸载软件。
- 不允许远程端下发 PowerShell、CMD、BAT、脚本或任意 Shell 命令。
- 不绕过 UAC，也不在没有 RustDesk 管理员服务的情况下偷偷提权。
- 第一版不做软件目录、批量部署、定时任务编排和版本升级策略；自愈只恢复已登记软件的缺失状态。

## 3. 安全边界

### 3.1 会话与权限

远程安装请求必须同时满足以下条件：

1. 远程连接已经完成 RustDesk 正常授权。
2. 目标端的“允许远程静默安装”策略已开启；默认关闭，可由定制客户端的管理员策略开启。
3. 远程连接拥有独立的“软件安装”权限，不复用终端权限，也不因为拥有文件传输权限而自动获得安装权限。
4. 目标端存在已安装且正在运行的 RustDesk Windows 服务。否则请求只返回“需要管理员服务”，不弹出隐藏 UAC 请求。

每个请求带有随机 `request_id`。目标端对相同 `request_id` 只处理一次，并且同一时刻只允许一个安装任务，避免重复下载和并发修改安装状态。

### 3.2 URL 校验

目标端在下载前和每次 HTTP 重定向后都使用 URL 解析器校验：

- scheme 必须是 `https`，大小写不敏感。
- hostname 必须精确等于 `szxinyu.com`，或精确以 `.szxinyu.com` 结尾；不能只做字符串后缀匹配，因而拒绝 `evil-szxinyu.com`。
- 不允许 URL 用户名、密码、IP 字面量和非 443 端口。
- URL 路径最终文件扩展名必须是 `.msi` 或 `.exe`，大小写不敏感。
- HTTP 客户端不接受跳转到白名单以外的最终地址。
- 不把 URL 中的查询参数或凭据写入普通日志；服务只记录请求 ID、主机、路径摘要和结果。

### 3.3 安装包完整性

远程请求必须包含期望的 SHA-256。目标端将下载内容写入同目录的 `.part` 文件，下载完成后计算摘要，摘要不一致时删除临时文件并拒绝安装。只有校验成功的文件才会原子改名为正式缓存文件。

安装成功后，目标端保存 URL、SHA-256、安装类型、检测规则、静默参数和最近一次结果，后续自愈只能使用这份登记信息。缓存文件损坏或被删除时，服务重新下载并再次校验。

## 4. 安装包清单

远程端下发的请求包含以下字段：

| 字段 | 要求 |
| --- | --- |
| `request_id` | 必填，单次请求唯一标识 |
| `software_name` | 必填，用于界面、日志和自愈记录 |
| `package_url` | 必填，经过 URL 白名单校验 |
| `sha256` | 必填，64 位十六进制 SHA-256 |
| `installer_type` | `msi` 或 `exe`，必须与扩展名一致 |
| `detection_type` | `msi_product_code`、`uninstall_display_name` 或 `exe_path` |
| `detection_value` | 与检测类型匹配的 ProductCode、显示名称或绝对路径 |
| `silent_args` | EXE 的参数列表；不经过 Shell 解析。MSI 只允许固定的静默安装流程 |
| `mode` | `download_only` 或 `download_and_install` |

`software_name` 和检测字段用于识别，不作为命令执行内容。EXE 参数通过参数数组传给安装程序，不调用 `cmd.exe` 或 PowerShell；禁止参数中出现需要 Shell 展开的重定向、管道和脚本调用形式。MSI 统一由服务调用 `msiexec.exe /i <package> /qn /norestart`，只追加经过白名单处理的 MSI 属性参数。

## 5. 组件与职责

### 5.1 远程连接协议

在现有 RustDesk 网络消息协议中增加 Windows 软件安装请求和状态消息。协议层只传输清单字段和状态，不传输任意命令；安装包内容通过现有文件传输能力或目标端 HTTPS 下载完成，第一版优先走 HTTPS 下载路径，避免把大文件塞进控制消息。

目标端收到请求后执行顺序为：鉴权与权限检查 → URL 校验 → 清单字段校验 → 检查软件状态 → 下载或读取已校验缓存 → 重新校验摘要 → 调用 Windows 服务安装器 → 保存自愈清单 → 回传结果。

### 5.2 Windows 安装服务

新增聚焦于 Windows 的安装器模块，负责：

- 使用 `%ProgramData%\\新育智慧校园\\remote-software\\packages` 保存安装包和 `.part` 文件。
- 使用 `%ProgramData%\\新育智慧校园\\remote-software\\state.json` 保存自愈清单和退避状态。
- 创建目录时设置为 SYSTEM 和本机 Administrators 可访问，普通用户不能修改清单。
- 使用已有 RustDesk Windows 服务进程执行下载、检测和安装。
- 将 MSI/EXE 子进程的退出码映射为成功、需要重启、失败三类结果；成功码为 `0`，MSI 的 `3010` 视为“成功但需要重启”。
- 安装完成后保留经过校验的缓存，清理未完成的 `.part` 文件。

### 5.3 自愈调度

Windows 服务启动时立即检查清单，并随后每 5 分钟检查一次。每条清单只在检测结果为缺失时执行恢复；已存在的软件不重复运行安装器。

失败任务采用退避：同一软件连续失败后至少等待 5 分钟、15 分钟、30 分钟再重试；一小时内最多尝试 3 次。超过次数后进入暂停状态，向远程端和本地日志报告失败，下一次服务重启再恢复检查。成功安装后清零失败计数。

### 5.4 Flutter 远程端界面

仅当目标平台为 Windows 且当前会话具有软件安装权限时，在远程会话操作区显示“远程安装”入口。弹窗提供：软件名称、下载地址、安装包类型、SHA-256、检测方式、检测值、EXE 静默参数，以及“仅下载”“下载并安装”按钮。

界面显示排队、下载中、校验中、已下载、检测中、安装中、已安装、安装成功、需要重启和失败状态。界面不展示目标端的中继服务器、API 或内置密钥配置。

## 6. 错误处理

目标端对错误返回稳定的错误类别和可读说明：

- `permission_denied`：会话未授权、策略关闭或软件安装权限关闭。
- `service_required`：RustDesk Windows 服务未运行。
- `invalid_url`：scheme、域名、端口、跳转或扩展名不符合规则。
- `invalid_manifest`：字段缺失、类型不匹配、检测值非法或 SHA-256 格式错误。
- `download_failed`：网络、HTTP 状态码或磁盘写入失败。
- `checksum_mismatch`：实际 SHA-256 与请求不一致。
- `already_installed`：检测到目标软件已存在，没有执行安装。
- `installer_failed`：安装程序返回未成功退出码。
- `recovery_paused`：自愈重试达到一小时内上限。

网络断开、远程端关闭窗口或服务重启不会留下半成品安装状态；下一次服务启动会清理 `.part` 文件，并根据完整清单重新判断。

## 7. 测试与验收

### Rust 测试

- URL 校验接受根域名和子域名，拒绝相似域名、HTTP、IP、凭据、非 443 端口和白名单外跳转。
- 清单校验拒绝空名称、错误扩展名、错误 SHA-256、非法路径和不支持的安装类型。
- MSI 命令构造固定使用 `/qn /norestart` 且不经过 Shell；EXE 参数不会生成 Shell 命令字符串。
- 检测器能区分“已安装”和“缺失”，并在缺失时进入下载/安装流程。
- 缓存摘要错误时拒绝安装并删除损坏缓存。
- 退避计数遵守 5/15/30 分钟和一小时三次上限。
- 未授权、策略关闭和服务缺失时不会下载或启动安装程序。

### Flutter 测试

- 非 Windows 目标不显示入口。
- 没有软件安装权限时不显示入口。
- URL、SHA-256、安装类型和检测字段校验错误可见。
- 下载中、安装中、成功、已安装和失败状态可正确展示。

### Windows Actions 验收

- 在 GitHub Actions Windows runner 上完成 Rust 单元测试、Flutter 分析/测试和 Windows 构建。
- 使用受控测试安装包验证 MSI 静默安装、已安装跳过和删除后自愈恢复。
- 验证发布构建只包含预期的 Windows 产物，且不改变现有中继、API、内置 key 的只读策略。

## 8. 兼容与迁移

旧版本升级后没有 `state.json` 时不会主动安装任何软件，行为保持不变。只有远程端成功提交并校验一份清单后，目标端才会开启该软件的自愈记录。删除清单或关闭“允许远程静默安装”策略后，服务停止新的下载和安装任务；已安装的软件不会被自动卸载。
